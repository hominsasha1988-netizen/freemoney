# Telegram Mini App — реферальна система (v4, з бекендом)

Повністю робочий Mini App + бот + сервер. Без npm-залежностей (потрібен лише **Node.js ≥ 22.13**).

## Що тепер працює по-справжньому

| Було (v3) | Стало (v4) |
|---|---|
| Баланс, реферали, заявки в `localStorage` (можна накрутити з консолі) | Усе в SQLite на сервері, клієнт лише показує |
| «Підписка» — демо-режим | Реальна перевірка через `getChatMember` |
| Реферали — кнопка «+ додати» в демо | Реферал рахується, коли друг пройшов перевірку підписки; рефереру приходить сповіщення |
| Фейковий лідерборд | Реальний топ за активними рефералами |
| Адмінка в браузері без захисту | Адмін = тільки ID з `ADMIN_IDS`, перевірка на сервері |
| Заявки на вивід нікуди не йшли | Заявка → сповіщення адміну в Telegram → «Виплачено / Відхилити» в адмінці → сповіщення юзеру |

Захист: підпис `initData` (HMAC) на кожному запиті, одноразові нагороди на рівні БД (гонки неможливі), атомарне списання балансу, повторна перевірка підписки перед виводом, ліміти запитів, екранування HTML, токен тільки зі змінних оточення.

## Запуск за 5 кроків

1. **Бот.** У @BotFather: `/newbot` → збережи токен.
2. **Канали.** Додай бота **адміністратором** у кожен канал, на який потрібна підписка (інакше `getChatMember` не працює).
3. **Сервер.** Задеплой (див. нижче) і задай змінні оточення з `.env.example`. Найважливіші: `BOT_TOKEN`, `ADMIN_IDS` (твій Telegram ID, дізнатись можна в @userinfobot), `PUBLIC_URL`.
4. **Mini App.** У @BotFather: `/newapp` → вибери бота → вкажи URL = твій `PUBLIC_URL` → **short name** = `app` (або свій, тоді задай `APP_SHORT_NAME`). Реферальні посилання мають вигляд `https://t.me/<бот>/<short name>?startapp=ref_<id>`.
5. **Перевір.** Напиши боту `/start` → «Відкрити додаток». Ти побачиш кнопку ⚙️ в адмінці.

Локально: `BOT_TOKEN=... ADMIN_IDS=... npm start` (без `PUBLIC_URL` бот працює через long polling; для Mini App потрібен https, напр. через `cloudflared tunnel`).

## Деплой

**Важливо про базу.** Дані лежать у файлі SQLite (`DB_PATH`, за замовчуванням `data/app.db`). На безкоштовному Render диск **не зберігається** — після кожного деплою/засинання база зникне разом з балансами. Потрібен постійний диск.

- **Render:** `render.yaml` у проєкті — Web Service з диском на `/var/data` (платний план Starter). `PUBLIC_URL` Render підставляє сам. Залишається задати `BOT_TOKEN` і `ADMIN_IDS`.
- **VPS / Railway / Fly.io:** `npm start`, змонтуй том і вкажи `DB_PATH=/шлях/до/тому/app.db`.
- Запускай **один інстанс** (ліміти запитів зберігаються в пам'яті, а SQLite — файл).

Бот сам вибирає режим: є https `PUBLIC_URL` → webhook (виживає засинання сервісу), інакше long polling. Перемикається змінною `BOT_MODE`.

## Адмін-панель (⚙️ у шапці, видно тільки адмінам)

- Заявки на вивід: адреса (тап — копіювати), «✓ Виплачено» (після того як ти **сам** відправив USDT) або «✕ Відхилити» (бонуси повертаються юзеру).
- Канали: додати/видалити (бот перевіряє, що має доступ до каналу).
- Налаштування: мін. сума виводу, бонус за друга, курс «бонусів за 1 USDT».

Виплати **ручні**: апка не відправляє крипту автоматично, вона веде облік і сповіщає. Автоматична виплата — окрема інтеграція з гаманцем/біржею.

## Правила нарахувань (змінюються в `game.js`)

- Реферер отримує `ref_bonus` (за замовчуванням 10), коли друг **уперше пройшов перевірку підписки**. Самореферали, неіснуючі реферери й «перепризначення» старих юзерів ігноруються.
- Рівні, бонуси й завдання рахуються за **активованими** рефералами.
- Вивід: USDT TRC20 (перевірка формату адреси), одна заявка на розгляді за раз.

## Структура

```
server.js     HTTP-сервер, API, адмін-логіка
bot.js        /start, webhook / long polling
auth.js       перевірка підпису initData
db.js         схема SQLite, транзакції
game.js       рівні, бонуси, завдання
config.js     змінні оточення
telegram.js   клієнт Bot API
public/       Mini App (index.html, app.js, styles.css)
test/         інтеграційні тести: npm test
```

## Тести

`npm test` — 13 інтеграційних тестів із підробленим Telegram API: підпис initData, підписка, реферали (дублі, self, гонки), одноразові нагороди, вивід, адмін approve/reject, відписка перед виводом, статика/path traversal, webhook-секрет.
